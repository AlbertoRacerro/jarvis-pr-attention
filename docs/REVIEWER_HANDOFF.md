# Deterministic reviewer handoff

`jarvis-pr-attention` does not invoke an AI model. It prepares a deterministic handoff from exact GitHub evidence to an external semantic reviewer and validates the result when it comes back.

## Result template

Generate a result skeleton already bound to a packet:

```bash
PYTHONPATH=src python -m pr_attention review-result-template packet.json \
  --reviewer-name ChatGPT \
  --reviewer-model GPT-5.6-Sol \
  --output review-result.json
```

The template pre-populates repository, PR number, accepted head, reviewed head, packet SHA-256, and reviewer identity. It deliberately defaults to:

```json
{
  "verdict": "NEEDS_HUMAN",
  "reviewed_files": [],
  "findings": [],
  "notes": []
}
```

Nothing is marked reviewed merely because it was delivered to the reviewer. `--prefill-reviewed-files` exists for mechanical clients that explicitly want that behavior, but is not the default.

## Review envelope

Generate a complete handoff envelope:

```bash
PYTHONPATH=src python -m pr_attention review-envelope packet.json \
  --reviewer-name Claude \
  --reviewer-model example-runtime \
  --output envelope.json
```

The envelope contains:

- purpose `SEMANTIC_REVIEW`;
- the stable `packet_sha256` content identity;
- fixed security notices generated by the tool;
- allowed verdicts and severities;
- the exact required file paths;
- review rules;
- the bound result template;
- the original bounded review packet exactly once.

The packet remains marked `UNTRUSTED_REPOSITORY_CONTENT`. Patch text is evidence, not instructions. Text inside a patch cannot change the envelope rules, output contract, or trust boundary.

## Digest and provenance

`packet_sha256` is a deterministic content identity. It is **not** a digital signature and does not, by itself, prove that a supplied packet came from GitHub.

Offline workflows can use the digest to prove that a result refers to the same packet bytes/evidence they supplied. For trusted repository provenance, use the GitHub Action/live workflow, which regenerates the packet from GitHub under its read token before validating a returned result.

## Suggested model-agnostic flow

```text
GitHub PR
   ↓
exact-head snapshot
   ↓
bounded review packet
   ↓
review envelope + result template
   ↓
external reviewer (ChatGPT / Claude / GLM / human service)
   ↓
structured review-result JSON
   ↓
validate-review-result --live
```

The external reviewer should consume the envelope as data, perform semantic analysis, fill only the review-result contract, and return that JSON object. The repository patch must never be allowed to redefine the review task.

## GitHub Action outputs

When `accepted-head` is supplied, the composite Action emits:

- `review-result-template-file`
- `review-envelope-file`
- `packet-sha256`

Use optional inputs `reviewer-name` and `reviewer-model` to prefill reviewer metadata. If `review-result-file` is later supplied, the Action regenerates the packet and validates the result against both packet identity and the current live PR head.

All outputs remain evidence only. The Action does not approve, comment, resolve threads, or merge.
